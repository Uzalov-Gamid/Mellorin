# English Grammar v1

`formats/english-grammar.json` composes reusable `grammar-study` with empty props. JERY prepares `.mellorin/english-grammar.json` only after an explicit request. First read the existing `Learning/English/grammar/process.md`, relevant notes and errors. The real process governs tails, four theory parts (one shown at a time), conspect, practice in chat and external iPad homework. Never replace or append instructions to process.md. This contract is appended only to app-owned `.mellorin/README.md`. Missing sources require a question; never generate default lessons, practice facts, statuses or a claim that a PDF was checked. Write prepared JSON atomically.

All fields below are required unless marked optional. File limit: 131072 UTF-16 code units. Unknown keys reject the reload. Text is plain escaped React text, with no HTML/code, fonts, colors or executable properties. Strings must be nonblank, reject angle brackets/control characters and are bounded as below. Sources are provenance supplied by JERY, not independent verification of their content.

- Root: `version:1`, `id` ≤100, `title` and `subtitle` ≤300, `source`, `stage` integer 0–4, `part` integer 0–3.
- `steps`: exactly five `{id,label}` objects in this order: `tail`, `theory`, `conspect`, `practice`, `homework`. Labels ≤60, normally `хвост`, `теория`, `конспект`, `практика в чате`, `домашка на iPad`. The app adds N из 4 to theory. Stage comes from JERY, never inferred from viewing pages or clicking answers.
- `parts`: exactly four objects `{title,subtitle,source,paragraphs,headers,rows,trap,hint}`. Title/subtitle ≤300, trap ≤2000, hint ≤500. Paragraphs: 0–8 arrays of runs. Headers: 1–4 strings ≤100. Rows: 1–12 arrays with exactly one run array per header. Every run array has 1–20 `{text,role?}` entries, text ≤1000. Optional role enum: `accent`, `success`, `warning`, `danger`, `muted`, `highlight`. Use semantic emphasis for endings/forms. Each part has its own source; it is the only theory part displayed.
- `practice`: `{id,question,source,options,answer?}`. Id ≤100, question ≤2000, options 2–6 distinct strings ≤300. Optional answer `{index,source,explanation}` requires a 0-based valid option index, actual source and explanation ≤2000. Omit it when no sourced key exists. Selecting a pill is local; “Ответить JERY” explicitly sends lessonId, practice id, source, question and selected answer. No answer key means no local grading. A sourced key is shown only after submission; all answers still go to JERY.
- `homework`: 0–12 `{pages,status,source}` entries; pages ≤200, status `waiting` or `checked`. Only actual data may claim checked. `homeworkHint` ≤1000 describes the real external process; requesting a check sends an intent, never changes status locally or reads iCloud automatically. Check buttons live in “Источники и загрузка урока”.
- `note`: `{path,status}` with status `waiting` or `ready`. Ready opens a bounded read-only in-vault preview, with visible read failure and Close. It does not launch an arbitrary URL or write notes. Waiting shows the supplied filename, without claiming it exists.

All source/note references must be relative Markdown paths under `Learning/English/`, ≤240 characters, ≤10 path segments, no empty/hidden/dot/traversal segments, leading/trailing segment whitespace, backslashes, controls, URL delimiters or percent encoding. Nested grammar/notes, English errors.md and process.md paths are allowed. Native `vault_read_text` additionally rejects outside-vault symlinks and oversized reads.

The block reads at mount and explicit reload only. Malformed/missing reload preserves the last valid lesson, theory part and answer state with a visible error. An explicit successful reload can adopt a different lesson id/source; it resets the viewed part to the supplied part and closes the previous note preview. Same-lesson successful reload keeps the viewed part. Every successful reload clears selection/submission, preventing a stale answer from grading new practice. Navigation preserves mounted state. No automatic JERY messages, model calls or direct content writes occur.

Synthetic checks: `npm run typecheck`, `npm test`, Rust format/Clippy/tests when seed changes, and `node scripts/visual-qa.mjs --screen Grammar --mockups ~/Documents/pulse-wt/design/mockups`. The adapter uses public mockup text in a synthetic bridge, all three widths and sidebar modes, then verifies part boundaries, navigation retention, explicit intents, stale/malformed reload and note navigation. Native app/config and one real refresh remain the lead orchestrator's responsibility.
