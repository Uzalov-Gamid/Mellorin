# English Writing v1

`formats/english-writing.json` composes `writing-study` with empty props. This bounded data-only block reads `.mellorin/english-writing.json` only at mount and on explicit load. It never renders HTML, writes study content, or invokes JERY automatically. Missing/invalid files show diagnostics; failed reload preserves the last valid assignment, draft, rewrite and review. Mounted screen panels retain state during navigation. A different assignment id/source is rejected while this screen holds a draft; restart the app after finishing to adopt a new assignment.

JERY must first read the existing `Learning/English/writing/process.md` and the actual selected materials. The process governs teaching, topics, stages and recording results. Do not overwrite or append app instructions to process.md. This contract is appended only to app-owned `.mellorin/README.md`. Missing information requires a question, never a fabricated assignment, target, plan, draft or review. Write the data file atomically (temporary file + rename). No real refresh is needed for synthetic tests.

Root JSON fields:

- `version`: 1; `id`: nonblank string ≤100; `title`: nonblank string ≤300; `source`: actual assignment/process source.
- `target`: `{min,max,source}`, integers 1 ≤ min ≤ max ≤10000, taken from the source. The displayed actual count uses Unicode letter/number words with internal apostrophes/hyphens; it never displays a fabricated count.
- `plan`: 1–10 `{text,source}` items; `watchOut`: 0–10 `{text,source}` items. Each text nonblank ≤1000. Every source must be `Learning/English/writing/<filename>.md` (one filename, ≤240, no slash/backslash/control/traversal). Source paths are inspectable in “Источники задания”. They are provenance supplied by JERY, not proof the app has verified the prose.
- `draft`: string ≤20000, initially empty unless it is the user's exact previously saved text. On same-assignment reload the local typed text wins, including whitespace. No text is generated by the app.
- Optional `review`: `{lessonId,draft,errors,mainErrors}`. `lessonId` must equal root id; `draft` is the EXACT nonblank reviewed text ≤20000, without trimming, normalization or newline changes. It is independent from root draft so a newer local draft can invalidate an older review.
- `errors`: 0–40 entries `{start,end,before,after,why}` sorted by start, no overlaps. Offsets are UTF-16 code units, 0-based half-open, 0 ≤ start < end ≤ draft.length. `before` must exactly equal draft.slice(start,end), nonblank ≤2000; `after` ≤2000 (empty means delete); `why` nonblank ≤2000. Numbers displayed automatically as 1..N, tied to both highlight and card. No markup interpretation.
- `mainErrors`: one or two unique 1-based error numbers; empty only when errors is empty. No invented summary: the brass note uses these numbered explanations.

Whole file ≤131072 UTF-16 code units. Unknown fields are discarded. Wrong types, excessive arrays, mismatched quotes, wrong lesson ids, overlapping/out-of-bounds ranges and invalid main-error references reject the entire reload.

Review appears only when its lessonId and exact draft match the current local text. Any edit hides highlights/cards immediately. Rewrite is an explicit local action, retains the original and starts with the whole text; no automatic JERY message. “Вернуться к проверке текста” permits sending the revised draft for another exact review. Only explicit preparation/review/result clicks send intents, guarded by readiness; errors remain visible for retry. Loading data and navigating never send messages. A result payload includes both originalDraft and the actual corrected draft; the app never writes errors/progress/session content.

Intent payloads:

- Prepare: no payload; asks JERY to read the process, real sources and this contract.
- Review: `{lessonId,source,draft}`; asks JERY to write a review with exact draft and UTF-16 spans.
- Result: `{lessonId,source,originalDraft,draft}`; asks JERY to review the correction and follow the existing process for actual records.

Root native checks: prepare synthetic process + JSON above; verify numbered highlight/card/count, rewrite and readiness; change one character and reload an old review (no stale marks); try malformed reload (text and last valid assignment retained); navigate away/back (draft/rewrite retained). Native config, app launch and real-process refresh remain root responsibilities.
